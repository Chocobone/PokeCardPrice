# Task #12: 프론트엔드 기반 및 홈·검색 화면 — 수행 계획서

## 수행 목표

#1의 임시 화면(백엔드 상태 표시)을 실제 앱 골격으로 바꾼다. 라우터·Pinia·API 클라이언트·반응형 레이아웃을 갖추고, 홈(검색창, 급등·급락 목록)과 검색 결과 화면을 만든다.
의존 이슈 #8(카드 검색·시세 조회 API)이 아직 없으므로 **API 계약 초안**을 먼저 정하고 목업 응답으로 화면을 완성한다. #8은 이 계약에 맞춰 구현하면 화면이 바로 실제 데이터로 동작한다.

## 범위

1. **개발 도구**: TypeScript 전환 (Q4), `vue-router`, `pinia` 도입. ESLint(`eslint-plugin-vue`, `typescript-eslint`) 도입(#1 인계). 단위 테스트 도구는 도입하지 않는다 (Q3, #15에서 정함).
2. **앱 골격과 라우팅**

   | 경로 | 화면 | 이 타스크 |
   |------|------|-----------|
   | `/` | 홈: 검색창, 급등·급락 목록 | 구현 |
   | `/search?q=&lang=&page=` | 검색 결과 | 구현 |
   | `/cards/:id` | 카드 상세 | 자리만 (#13) |
   | `/login`, `/collection` | 로그인·내 컬렉션 | 만들지 않음 (#14) |
   | 그 밖 | 찾을 수 없음 | 구현 |

3. **반응형 레이아웃**: 헤더(서비스 이름, 어느 화면에서나 쓰는 검색창), 본문, 푸터(데이터 출처 표기: TCGdex, PokéAPI, 시세 소스). 모바일(360px)~데스크톱 폭 대응. 목록은 화면 폭에 따라 열 수가 바뀌는 카드 격자.
4. **API 클라이언트**: `fetch` 래퍼(`/api` 기준 주소, 오류 형식 통일, 요청 취소, 제한 시간), 엔드포인트 함수(카드 검색, 급등·급락, 상태 확인).
5. **API 계약 초안** (`mydocs/tech/api_contract.md`, 신규): 이 타스크가 쓰는 엔드포인트의 요청·응답 형식. #8 구현의 입력이 된다.

   | 엔드포인트 | 용도 |
   |------------|------|
   | `GET /cards?q=&lang=&page=&size=` | 카드 검색. `q`는 카드 이름(영·일)·한글 종 이름·세트 ID·번호 |
   | `GET /rankings/movers?period=7d\|30d&direction=up\|down&limit=` | 급등·급락 순위 |

   응답 항목은 카드 ID, 언어, 이름, 세트(ID·이름), 번호, 이미지, 한글판 여부(`has_ko_edition`), 대표가와 통화, 변동률을 포함한다. 필드명·형식은 구현 계획서에서 확정한다.

6. **목업 모드** (Q1): `VITE_API_MOCK=true`이면 API 클라이언트가 내장 목업 응답을 돌려준다. 목업 데이터는 #5에서 적재한 실제 카탈로그 표본(세트·카드 이름·이미지 URL) 형태로 만든다. #8 완성 후에는 끄기만 하면 된다.
7. **상태 관리 (Pinia)**: 검색(질의·결과·쪽·로딩·오류), 급등·급락(기간·방향별 결과). 검색어는 URL 쿼리와 동기화해 새로고침·뒤로 가기·링크 공유가 되게 한다.
8. **화면**
   - 홈: 검색창, 급등·급락 목록(기간 7일/30일 전환, 각 상위 N개).
   - 검색 결과: 카드 격자(이미지, 이름, 세트, 번호, 언어 배지, 한글판 배지, 대표가), 쪽 넘김, 결과 없음·로딩·오류 상태.
   - 이미지가 없는 카드(`ko` 카드 등)는 대체 이미지를 쓴다.
9. **검증·문서**: 타입 검사(`vue-tsc`), ESLint, `npm run build`. 화면은 목업 모드에서 데스크톱·모바일 폭으로 확인한다 (단위 테스트 없음, Q3). 실행 방법은 기술 문서와 `CLAUDE.md`에 반영한다.

## 핵심 설계 원칙

- **계약 먼저, 목업으로 개발**: 화면은 API 계약에만 의존한다. 목업은 API 클라이언트 한 곳에서만 갈아 끼우고, 화면·스토어 코드는 목업 여부를 모르게 한다.
- **URL이 상태의 기준**: 검색어·필터·쪽은 URL 쿼리에 두고, 스토어는 URL에서 읽는다.
- **의존성 최소화**: UI 프레임워크 없이 CSS 변수와 직접 작성한 컴포넌트로 시작한다 (Q2). 추가하는 패키지는 구현 계획서에 근거를 남긴다.
- **한국어 사용자 기준**: 한글 종 이름 검색을 기본 사용 흐름으로 두고, 일본판 카드에는 한글판 여부를 표시한다 (#5 `has_ko_edition`).
- **#5와 충돌하지 않는 변경**: 이 브랜치는 `local/task5`(3단계 커밋 `21970a8`)에서 분기했다. #5가 바꾸는 백엔드·수집기·`Docker/` 파일은 건드리지 않고, `src/frontend/`와 신규 문서만 바꾼다. 공용 파일(`CLAUDE.md`, 오늘 할일)은 #5가 고치지 않는 위치에만 추가한다.
