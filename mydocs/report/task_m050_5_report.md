# Task #5 최종 결과보고서: 카드 카탈로그 수집기

> **작성일**: 2026-11-17
> **브랜치**: `local/task5`
> **마일스톤**: M050 (v0.5.0)

## 개요

TCGdex에서 영어판·일본판·한글판의 세트·카드·변형을 받아 #4의 카탈로그 테이블에 적재하는 수집기를 만들었다. 수집기는 그 밖에 다음을 맡는다.
- 한글판 카드를 같은 일본판 카드에 자동으로 연결한다.
- 한글판이 나온 일본판 카드에 `has_ko_edition`을 표시한다.
- 포켓몬 종 이름(한·일·영 1,025종)을 적재해 한글 이름 검색의 바탕을 만든다.

수집기는 매일 05:30 KST에 새 세트·새 카드만 받고, 매월 1일에는 모든 카드 상세를 다시 받는다. 별도 장비에서 수집기만 돌릴 수 있도록 실행 스크립트와 설명서를 추가했다(작업지시자 요청).

개발 DB에 전체 적재를 마쳤다.

| 항목 | 수 |
|------|-----|
| 세트 | 509 |
| 카드 | 37,307 |
| 변형 | 48,930 |
| 한글판 자동 연결 | 239/239 |
| `has_ko_edition` | 4,871 |
| 종 이름 | 1,025 |

이제 #6(시세 수집)은 `card_variants`에 가격을 붙이고, #8(검색 API)은 한글 종 이름으로 세 언어 카드를 찾을 수 있다.

## 발견 사항

- **TCGdex 데이터 이상**:
  - 일부 카드의 도감 번호가 소수다(`384.1`, 레쿠쟈 4장). 정수 부분만 저장한다.
  - 세트 상세 404가 9개 있다(`ko` 한국 전용 구성 세트 4개 포함).
  - `ko` 카드와 최신 일본판 카드는 이미지가 없다.
- **TCGdex 일시 장애**: 몇 시간 단위로 `503`을 짧게 낸다. 요청 단위 재시도(1→2→4초)로는 부족해, 30초 뒤 세트 단위로 다시 시도하게 했다. 1차 적재에서는 DNS 장애로 `ko` 세트 목록 전체를 받지 못했다.
- **오래된 `auto` 연결 삭제를 추가했다** (3단계). 일본판 카드 정보가 수정되면 규칙에 맞지 않는 연결이 남기 때문이다. `manual` 연결은 건드리지 않는다.
- **sqlc는 여러 인자 `unnest(a, b, ...)`를 해석하지 못한다.** 선택 목록에 열마다 `unnest`를 두었다.
- **테스트 DB 동시 사용**: `go test ./...`는 패키지를 병렬로 실행해, DB 테스트가 같은 DB를 비우며 충돌했다. 패키지별 테스트 DB(`dbtest.Pool(t, "<패키지명>")`)로 나눴다.
- **`ko` 수록 범위**: TCGdex `ko`는 2016-12 ~ 2024-06 세트만 있다. 이후 한글판은 표시되지 않는다 (#7에서 처리 방식 결정).

## 계획 대비 차이

| 계획 | 실제 | 사유 |
