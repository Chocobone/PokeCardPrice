# Task #2: 시세 데이터 소스 조사 — 수행 계획서

## 수행 목표

카드 카탈로그, 해외 시세, 환율, 국내 거래가 각각에 대해 실제로 쓸 수 있는 데이터 소스를 확인하고 **1차 수집 소스를 확정**한다.
결과는 #4(DB 스키마), #5(카탈로그 수집기), #6(해외 시세 수집기), #7(국내 거래가 수집기)이 다시 조사하지 않고 바로 설계에 쓸 수 있는 문서로 남긴다.

## 범위

1. **카드·해외 시세 API** (TCGdex, pokemontcg.io)
   - 카드·세트 필드, TCGplayer·Cardmarket 가격 포함 여부, 가격 필드의 의미(시장가·최저가 등)와 통화, 갱신 주기
   - 호출 한도, API 키 정책, 이용 조건
   - 한글판 카드 지원 여부 (국내 거래가와 카드를 연결할 수 있는지 판단하는 근거)
2. **환율 API**: 후보 2~3개의 원화(KRW) 지원, 무료 한도, 갱신 주기, 키 정책, 과거 환율 제공 여부를 비교한다.
3. **국내 거래가 소스** (`mydocs/tech/domestic_price_sources.md` 사전 조사의 후속)
   - 번개장터·중고나라·KREAM·포케폴리오의 이용약관 원문 검토 (자동 수집, 데이터 재사용 조항)
   - `robots.txt` 재확인, 공개 페이지에서 확인 가능한 범위의 응답 구조 확인
   - 포케폴리오 제휴 API의 공개 안내 내용 확인과 문의 초안 작성
4. **소스 확정**: 항목별 1차 소스와 대체 소스, 소스별 가격 성격(실거래 / 호가 / 판매가), #4~#7에 넘길 설계 입력을 정리한다.

### 범위 밖

- 수집기·어댑터 구현 → #5, #6, #7
- DB 테이블 설계 → #4 (본 타스크는 필요한 필드와 가격 성격만 정리해 넘긴다)
- Go 프레임워크, 스케줄러 방식 선정 → #3

## 핵심 설계 원칙

- **원문 확인**: 호출 한도·약관·가격 필드는 공식 문서와 약관 원문, 실제 API 응답으로 확인하고 출처 URL과 확인일을 남긴다. 확인하지 못한 항목은 "미확인"으로 표시한다.
- **접근 제한 준수**: 로그인, 봇 차단, `robots.txt` 금지 경로를 우회하지 않는다. 사전 조사에서 번개장터 `robots.txt`가 AI 크롤러를 전면 차단하는 것으로 확인되었으므로, 이 조건과 약관을 먼저 검토한다. 접근할 수 없는 소스는 "확인 불가"로 기록하고 판단을 작업지시자에게 넘긴다.
- **최소 호출**: 응답 구조 확인에 필요한 만큼만 소량으로 요청한다.
- **외부 발신 분리**: 포케폴리오 문의는 초안까지만 작성한다. 발송은 작업지시자가 직접 하거나 별도로 승인한다.
- **비밀 정보 보호**: 저장소가 공개이므로 API 키와 개인 정보를 문서·커밋에 남기지 않는다.
- **법적 판단의 한계**: 약관 검토는 조항을 정리해 위험을 판단하는 수준이며 법률 자문이 아니다. 위험이 남는 소스의 포함 여부는 작업지시자가 결정한다.
