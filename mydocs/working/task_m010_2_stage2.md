# Task #2 단계2 완료 보고서: 환율 API 비교

## 수행 내용

Frankfurter, open.er-api.com, 한국수출입은행에 한국은행 ECOS를 더해 환율 소스를 비교했다.
키가 필요 없는 Frankfurter와 open.er-api.com은 USD·EUR→KRW의 당일 값을 호출했다. 과거 날짜 값은 Frankfurter에서만 얻었다.
결과는 `mydocs/tech/price_data_sources.md` 7절과 결론에 추가했다.

| `mydocs/working/task_m010_2_stage2.md` | 본 보고서 |

## 발견 사항

1. **Frankfurter v2 혼합값이 1차 후보로 가장 적합하다.** 키가 필요 없고, 과거 날짜와 주말 값을 제공하며, 문서가 로컬 저장을 권장한다.
2. **후보 간 차이는 작았다.** 당일 값은 최대 0.13%, 2026-10-15 값은 최대 0.25% 차이가 났다. 다만 키가 없는 후보끼리의 비교이며, 표본은 두 날짜뿐이다.
3. **같은 서비스 안에서도 값 기준이 다르다.** Frankfurter의 일요일 호출에서 혼합값은 2026-11-01 값, ECB 값은 2026-10-30 값을 반환했다. 환율과 함께 값 기준일과 제공처를 저장해야 한다.
4. **open.er-api.com은 이용 조건이 맞지 않을 수 있다.** 출처 링크 표기가 필수이고 재배포가 금지된다. 환율을 프로그램으로 제공하는 제품·서비스에서의 사용도 금지되어, 우리 API가 환율 값을 그대로 내보내면 충돌할 수 있다.
5. **한국수출입은행은 대체 후보이지만 확인이 부족하다.** 공공데이터포털의 "이용허락범위 제한 없음"은 확인했다. 그러나 공식 안내 페이지가 빈 응답을 반환했고 키가 없어 호출도 하지 못했다.

## 계획과 달라진 점

- **후보 추가**: 국내 공식 기관 자료인 한국은행 ECOS를 추가했다. 공식 문서를 읽지 못해 대부분 `미확인` 또는 `2차 자료`이다.
- **API 버전 변경**: 처음에 v1을 호출했다가, v1이 지원 중단 상태임을 문서에서 확인하고 v2로 재호출했다. 10-15의 ECB 유로 값은 v2로 재호출하지 않아 v1 값을 사용했고, 표에 표시했다.

## 접근 규칙 준수 점검

- 후보 조회 전에 `robots.txt`를 먼저 확인했다. `api.frankfurter.dev`, `frankfurter.dev`, `www.exchangerate-api.com`, `ecos.bok.or.kr`은 허용이고, `open.er-api.com`은 파일이 없으며(404), `oapi.koreaexim.go.kr`은 robots 대신 일반 HTML을 반환했다. `www.koreaexim.go.kr`은 응답이 없었다(HTTP 000).
- 키 발급, 로그인, 키 없는 인증 시도는 하지 않았다. 한국수출입은행·ECOS의 환율 API는 호출하지 않았다.
- open.er-api.com의 추측 경로 1건을 호출했으며 404였다. 문서 표에 추측 경로임을 밝혔다.
