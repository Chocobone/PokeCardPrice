# Task #3 단계1 완료 보고서: 웹 프레임워크 비교

## 수행 내용

표준 라이브러리 `net/http`, Gin v1.12.0, Echo v5.4.4로 같은 기능의 예제를 만들고, 같은 테스트 8개를 적용해 비교했다.
예제 기능은 경로 변수, 쿼리·본문 바인딩과 검증, 인증 그룹, 로그·패닉 복구·CORS 미들웨어, JSON 404·405, 정상 종료이다.
예제는 세션 임시 폴더에 두고 `golang:1.27-alpine3.24` 컨테이너에서 빌드·실행했다.

결과는 `mydocs/tech/backend_stack.md`의 "1. 웹 프레임워크" 절에 정리했다.

## 발견 사항

1. **Echo v5의 사용자 정의 오류 처리기는 응답 커밋 여부를 확인해야 한다.** 확인하지 않으면 `RequestLogger`와 프레임워크가 처리기를 두 번 호출해 오류 응답이 두 번 쓰인다. 처음 구현에서 테스트 6개가 이 문제로 실패했고, `Committed` 확인을 넣어 해결했다.
2. **Gin의 검증 오류 메시지는 내부 구조체 이름을 드러낸다.** 또 `required`는 0을 누락으로 처리한다.
3. **Gin은 모듈 그래프가 56개이다.** QUIC, MongoDB 드라이버 등 이 프로젝트에 필요 없는 모듈이 포함된다.
4. **`net/http`는 404·405 응답을 JSON으로 바꾸는 데 응답 래퍼가 필요하다.** 동작은 하지만 깨지기 쉬운 방식이다.
5. **Docker Desktop이 꺼져 있어 작업 전에 실행했다.** compose 서비스 3개는 기동 후 정상(db healthy)이다.

## 잠정 판단

Echo v5가 가장 유력하다. 필요한 미들웨어가 내장되어 있고, 오류를 한 곳에서 처리할 수 있으며, 의존성이 적다. 선정은 2·3단계 결과와 함께 3단계에서 확정한다.

## 계획과 달라진 점

- Echo는 최신 메이저 버전인 v5로 비교했다. v4도 계속 릴리스되고 있으나 신규 프로젝트에는 v5가 맞다고 판단했다.
- 측정 항목의 "유지 상태"는 모듈 프록시의 릴리스 날짜로 확인했다. 저장소 커밋 활동은 확인하지 않았다.
