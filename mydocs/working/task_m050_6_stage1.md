## 발견 사항

1. **두 연결 방법은 서로 보완한다.** A는 프로모처럼 같은 번호의 상품이 여럿인 세트에, B는 TCGdex에 가격 정보가 없는 카드와 일본판에 강하다. 겹치는 2,285건은 모두 같은 결과였다.
2. **TCGdex 카탈로그에 리버스·홀로 변형이 빠진 실물 세트가 약 30개 있다** (`bw8`~`sm12` 시기 등). 예: `sm1`은 172장 모두 `normal`만 있으나, TCGplayer에는 179개 리버스 홀로 가격이 있다. 이 세트들의 리버스 가격은 붙일 변형이 없어 버려진다.
3. **카탈로그에 TCG Pocket(디지털 게임) 세트 2,480장이 들어 있다** (`A1`~`B2a`, `P-A`, TCGdex 시리즈 `tcgp`). 실물 카드가 아니라 가격이 없고, 검색 결과(#8·#12)에도 섞인다.
4. **초판 세트**: TCGplayer 기본 그룹은 무제한판이라 `Normal`·`Holofoil`을 `unlimited`·`unlimited_holofoil`로 연결한다. 초판은 별도 그룹(`Base Set (Shadowless)` 등)이고, 변형 7종으로 Shadowless를 구분할 수 없어 이번에는 연결하지 않는다.
5. **일본판 패턴 상품** (`Poke Ball Pattern`, `Master Ball Pattern`)은 두 상품이 TCGdex의 리버스 변형 하나에 대응해 구분할 수 없다. 연결하지 않는다 (`SV2a` 리버스 153개).
6. 일본판은 TCGCSV `subTypeName`이 카드의 홀로 여부를 나타낼 뿐 별도 판이 아니다. 카드 변형이 하나면 그 변형에 연결한다.
7. Cardmarket `0` 값은 거래 없음으로 보고 저장하지 않는다. 같은 카드의 변형들이 Cardmarket 상품 ID를 공유하므로 Cardmarket은 `external_ids`에 저장하지 않는다.

## 구현 계획 조정 (제안)

- 방법 A는 TCGdex 카드 상세 응답에서 나오므로, Cardmarket 수집(4단계 범위)과 TCGCSV 외부 ID 연결(3단계 범위)이 같은 응답을 쓴다. 3단계에서 TCGdex 카드 상세 → `pricing.tcgplayer` 상품 ID 추출을 함께 구현하고, 4단계는 그 응답의 Cardmarket 필드 저장만 더한다.
- 실행 흐름은 "환율 ‖ TCGCSV 가격 받기(저장된 `external_ids`로 연결·저장) ‖ TCGdex 상세 순회(Cardmarket 저장 + A 결과로 `external_ids` 갱신)"로 병렬 실행하고, 끝에 TCGCSV 중 연결 못 했던 가격 행을 갱신된 `external_ids`·B로 다시 연결해 저장한다. 첫 실행(빈 `external_ids`)에서도 같은 날 모든 연결이 된다. 세부는 2단계 보고서에서 확정한다.
