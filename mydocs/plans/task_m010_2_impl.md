## 공통 조사 규칙

### 기록 형식

- 모든 사실 항목에 **출처 URL과 확인일**을 남긴다.
- 항목별 확인 상태를 다음 네 가지로 표시한다.

| 표시 | 의미 |
|------|------|
| `응답 확인` | 실제 API·페이지 응답으로 확인 |
| `문서 확인` | 공식 문서, 약관 원문으로 확인 |
| `미확인` | 확인할 공식 자료나 응답을 찾지 못함 |
| `확인 불가` | 로그인, 봇 차단, `robots.txt` 금지 등으로 접근하지 않음 |

### 접근 규칙

- 사이트를 조회하기 전에 `robots.txt`를 먼저 확인한다. 금지 경로와 AI 크롤러 차단 대상은 조회하지 않는다.
- 로그인이 필요한 페이지, 앱 내부 API, 비공개 엔드포인트는 호출하지 않는다.
- 봇 차단을 넘기 위한 수단(TLS 위장, 브라우저 자동화, User-Agent 변경, 차단 우회 도구)을 쓰지 않는다.
- 소스별 요청은 응답 구조 확인에 필요한 최소량(엔드포인트당 1~3회)으로 하고, 요청 사이에 간격을 둔다.

### 작업지시자 협조가 필요한 경우

AI 도구로 볼 수 없는 약관·페이지는 `확인 불가`로 기록한 뒤, 작업지시자에게 **직접 열람 또는 원문 전달**을 요청한다. 전달받은 내용은 "작업지시자 제공"으로 출처를 표시한다.

### 저장소 반영 기준

- 공개 저장소이므로 API 키, 쿠키, 개인 정보, 판매자 정보를 문서·커밋에 남기지 않는다.
- 원본 응답은 저장소에 넣지 않고 세션 임시 폴더에만 둔다. 문서에는 구조 파악에 필요한 필드만 발췌한다.
- 약관은 전문을 옮기지 않고 해당 조항의 번호와 요지만 인용한다.

## 1단계: 카드·해외 시세 API 조사

### 목표

TCGdex와 pokemontcg.io를 같은 기준으로 비교해, 카탈로그와 해외 시세에 쓸 소스를 판단할 근거를 만든다.

### 구현

**`mydocs/tech/price_data_sources.md`** — 신규 작성 (`tech_investigation_template.md` 형식), 해외 API 절:

| 비교 항목 | 확인 내용 |
|-----------|-----------|
| 카드·세트 필드 | 식별자, 이름, 세트, 수록 번호, 레어도, 이미지, 세트 전체 조회와 페이지네이션 |
| 가격 필드 | TCGplayer·Cardmarket 포함 여부, 필드별 의미(시장가·최저가·평균가 등), 통화, 변형별 구분(홀로·리버스 등) |
| 가격 신선도 | 갱신 주기, `updatedAt` 유무, 과거 가격 이력 제공 여부 |
| 호출 조건 | 호출 한도, 키 필요 여부, 무키 호출과 키 호출의 차이 |
| 이용 조건 | 라이선스, 재배포·저장 허용 여부, 출처 표기 의무, 비상업·학생 프로젝트 해당 여부 |
| 언어 지원 | 한글판·일본판 카드 존재 여부, 같은 카드를 언어 간에 연결할 식별자 유무 |
| 운영 안정성 | 공식 문서의 서비스 상태, 공지된 변경·종료 예정, 최근 유지 보수 여부 |

확인 절차:

1. 공식 문서와 이용 조건을 읽는다.
2. 같은 샘플 카드 3종으로 두 API를 호출한다. 샘플은 최신 세트 1종, 구세트 1종, 한글판 존재 카드 1종으로 한다.
3. 응답의 가격을 TCGplayer·Cardmarket 공개 페이지 값과 조회 가능한 범위에서 대조한다.

API 키가 있어야 확인되는 항목은 무키 범위만 조사하고 `미확인`으로 표시한 뒤 키 발급 필요 여부를 보고한다. 키 발급은 작업지시자가 판단한다.

## 2단계: 환율 API 비교

### 목표

달러·유로 시세를 원화로 환산할 환율 소스의 1차안과 대체안을 제시한다.

### 구현

**`mydocs/tech/price_data_sources.md`** — 환율 절 추가

조사 시작 후보는 한국수출입은행 환율 API, Frankfurter, open.er-api.com이며, 조사 중 더 적합한 후보가 나오면 교체하고 이유를 기록한다.

| 비교 항목 | 확인 내용 |
|-----------|-----------|
| 통화 | KRW, USD, EUR 지원 (Cardmarket 유로 가격 환산 때문에 EUR 필수) |
| 기준 | 매매기준율·중간값 등 환율의 성격, 원 데이터 출처 |
| 갱신 | 갱신 주기, 주말·공휴일·장 시작 전 응답 동작 |
| 과거 환율 | 날짜 지정 조회 가능 여부 (수집 실패일 보정, 초기 이력 환산에 필요) |
| 호출 조건 | 무료 한도, 키 필요 여부, 이용 조건, 출처 표기 의무 |

후보별로 USD→KRW, EUR→KRW의 당일 값과 과거 1개 날짜 값을 호출해, 후보 간 차이를 표로 비교한다.

**`mydocs/working/task_m010_2_stage2.md`** — 단계별 완료 보고서

### 검증

- 후보별 실제 호출 결과와 호출 시각이 기록되어 있다. 키가 필요해 호출하지 못한 후보는 `문서 확인`으로 구분한다.
- 후보 간 환율 차이가 어느 정도인지 수치로 제시되어 있다.
- 주말·공휴일 처리 방식이 확인되었거나 `미확인`으로 표시되어 있다.

## 3단계: 국내 소스 약관·응답 구조 검토

### 목표

번개장터, 중고나라, KREAM, 포케폴리오를 각각 수집할 수 있는지 판단하는 데 필요한 근거를 정리하고, 포케폴리오 문의 초안을 작성한다.

### 구현

**`mydocs/tech/domestic_price_sources.md`** — 사전 조사 문서에 후속 조사 결과 추가

소스별로 다음 순서로 확인한다.

1. `robots.txt`를 다시 확인하고 2026-10-29 결과와 비교한다.
2. 약관 원문에서 자동 수집, 데이터 복제·재사용, 상업적 이용, 제3자 제공 조항을 찾아 조항 번호와 요지를 기록한다.
3. 접근 규칙이 허용하는 범위에서만 공개 페이지 구조를 확인한다. 판매 완료 여부, 가격, 상품명, 등록일 필드의 존재를 확인하고, 판매자 정보는 기록하지 않는다.
4. 소스별 위험을 분류한다.

| 위험 등급 | 기준 |
|-----------|------|
| 낮음 | 공식 API 또는 제휴 등으로 이용이 명시적으로 허용됨 |
| 중간 | 금지 조항이 불명확하고 `robots.txt`도 허용하나, 해석 위험이 남음 |
| 높음 | 약관이나 `robots.txt`가 자동 수집을 금지함, 또는 로그인 뒤에만 볼 수 있음 |
| 판단 불가 | 약관이나 구조를 확인하지 못함 |

번개장터는 사전 조사에서 `robots.txt`의 AI 크롤러 전면 차단을 확인했으므로, 이 정책이 유지되면 AI 도구로 페이지를 조회하지 않는다. 약관은 작업지시자 제공 내용으로 검토한다. KREAM의 로그인 필요 영역은 조회하지 않고 `확인 불가`로 기록한다.

**`mydocs/tech/pokepolio_inquiry_draft.md`** — 포케폴리오 제휴 API 문의 초안 (신규)

프로젝트 소개(학생 텀프로젝트), 필요한 데이터 범위, 예상 호출량, 비용, 출처 표기 조건, 학생 프로젝트 허용 여부를 묻는 내용으로 작성한다. 연락처 등 개인 정보는 자리 표시자로 두어 저장소에 남기지 않는다. **발송하지 않는다.**

**`mydocs/working/task_m010_2_stage3.md`** — 단계별 완료 보고서. 작업지시자에게 필요한 일(약관 원문 전달, 문의 발송 여부)을 명시한다.

### 검증

- 4개 소스 모두 위험 등급과 근거가 있다. `판단 불가`이면 그 이유와 필요한 조치가 있다.
- 약관 인용에 조항 번호, 원문 URL, 확인일이 있다.
- 문의 초안과 문서에 개인 정보, 판매자 정보, 약관 전문이 없다.

## 4단계: 소스 확정 및 후속 타스크 설계 입력 정리
