## 배경

작업지시자 결정(2026-10-29)으로 국내 거래가를 1차 수집 범위에 포함한다. 계획서에는 국내 소스로
KREAM만 언급되어 있으므로, KREAM 외에 국내 거래가를 수집할 수 있는 사이트가 있는지 조사한다.
본 문서는 웹 검색과 각 사이트 첫 화면, `robots.txt` 확인 수준의 **사전 조사**이며, 이용약관 원문
검토와 실제 응답 구조 분석은 타스크 #2에서 수행한다.

## 결론

1. **KREAM 외에도 국내 거래가 소스는 있다.** 1차 거래처로는 번개장터·중고나라, 집계 서비스로는
   포케폴리오가 가장 쓸 만하다.
2. **공식 공개 API가 있는 국내 소스는 없다.** 유일하게 포케폴리오가 제휴 형태의 실거래가 API를
   안내하고 있다.
3. KREAM은 시세 조회에 로그인이 필요해 자동 수집이 어렵고, 약관 위반 위험도 가장 크다.
4. 번개장터·중고나라는 판매 완료 데이터에 호가가 섞여 있고 상품명이 자유 텍스트다. 그래서
   카드 매칭과 이상치 제거 가공이 필요하다.
5. 다른 집계 서비스의 화면을 긁어 오는 방식은 2차 가공물이라 출처와 정확도가 불분명하다.
   저작권·약관 측면에서도 위험이 있어 수집 대상으로 권장하지 않는다.

## 적용 방향 (타스크 #2에서 확정)

- **1순위**: 포케폴리오 제휴 API 이용 가능 여부와 조건(비용, 학생 프로젝트 허용 여부)을 문의한다.
- **2순위**: 번개장터·중고나라 판매 완료 건을 수집한다. 약관 원문을 검토하고, 요청 간격을
  제한해 소량만 수집하는 것을 전제로 한다.
- **KREAM**: 약관 원문을 검토하고, 로그인 없이 볼 수 있는 범위를 확인한 뒤 포함 여부를 정한다.
- 수집기는 소스별 어댑터 구조로 설계해, 소스를 추가하거나 뺄 때 스케줄러를 고치지 않아도 되게 한다.
- 가격 이력 테이블에 **가격 성격(실거래 / 호가 / 판매가)** 컬럼을 두어, 평균가를 계산할 때 구분할
  수 있게 한다.

### 번개장터

약관과 페이지 구조 모두 조회하지 않았다(`확인 불가`). 공개 API 부재는 사전 조사 내용이며 이번에 재확인하지 않았다.

### 중고나라

**약관** (`미확인`): `/terms`와 `/post-policy`("게시글 수집 및 이용 안내")는 HTTP 200이지만, 정적 응답에 본문이 없고 사이트 공통 영역만 있었다. 브라우저 렌더링이나 내부 API 호출은 접근 규칙에 따라 시도하지 않았다. 페이지 제목으로 볼 때 `/post-policy`에 수집 관련 내용이 있을 수 있어 우선 확인이 필요하다.

**공개 페이지 구조** (`응답 확인`, 검색 1회·상품 1건, 필드 이름만 확인)

| 필요 항목 | 검색 결과 | 상품 페이지 |
|-----------|-----------|-------------|
| 상품명 | `title` | `productTitle` |
| 가격 | `price` | `productPrice`, `deliveryPrice` |
| 날짜 | `sortDate` | `sortDate`, `updateDate` |
| 판매 상태 | `state` (50건 모두 0) | `productStatus` (0), `schema.org` InStock |
| 상품 상태 | - | `productCondition` |

- **판매 완료 건을 얻는 방법은 확인하지 못했다.** 기본 검색 50건의 `state`는 모두 0이었고, 판매 완료를 나타내는 코드 값과 조회 조건은 `미확인`이다. 국내 시세의 핵심 조건이므로 약관 확인 후 재검토한다.
- 판매 상태가 0인 표본은 호가로 취급해야 한다.
- 상품 페이지 데이터에 판매자 필드(`seller`, `nickName`, `storeSeq` 등)가 함께 있다. 수집기는 이 값을 저장하지 않아야 한다. 확인에 쓴 원본 HTML은 삭제했다.

### KREAM

`robots.txt`가 HTTP 500을 반환해 약관과 상품 페이지를 조회하지 않았다(`확인 불가`). 로그인이 필요한 시세 영역은 조회 대상이 아니다.

### 3단계 판단

1. **현재 근거로 수집을 진행할 수 있는 국내 소스는 포케폴리오 제휴 API뿐이다.** 다만 조건이 맞아야 하고 약정 전에는 사용할 수 없다. (2026-11-02 제외 결정, 아래 절 참고)
2. 포케폴리오 화면을 수집하는 방식은 약관 위반 위험이 커서 제외한다.
3. 번개장터·중고나라·KREAM은 약관을 확인하기 전까지 1차 소스로 올리지 않는다.
4. 포케폴리오 API도 카탈로그와 이미지를 제공하지 않고, 시세 보유 카드가 1,804장으로 표기되어 있다. 한글판 카탈로그는 별도 해결이 필요하다.

### 국내 거래가 대체 방안

외부 수집 없이 국내 시세 요구를 채우는 방법이다. 4단계에서 하나 이상을 골라 확정한다.

| 방안 | 내용 | 장점 | 한계 |
|------|------|------|------|
| **A. 일본판 대리 시세** | 한글판은 일본판과 세트 코드·수록 번호가 같은 경우가 많다(1단계 표본 `SV5K-001`). 일본판 가격(JPY 또는 해외 시장가)을 원화로 환산해 "일본판 기준 참고가"로 표시 | 공식 API 사용, 약관 문제 없음, 자동 수집 가능 | 국내 실거래가가 아님. 세트 코드 일치 범위 확인 필요(#5) |
| **B. 사용자 거래가 직접 입력** | 앱 사용자가 자신이 사고판 가격·날짜·상태를 등록하고, 이를 집계해 국내 시세로 표시 | 외부 약관과 무관, 실거래 성격 | 초기 데이터 부족, 허위 입력 검증 필요, 입력 기능 구현 추가 |
| **C. 작업지시자 수동 입력** | 시연 대상 카드 일부의 국내 거래가를 작업지시자가 직접 확인해 관리자 입력 | 구현 단순, 시연 가능 | 자동 수집 아님, 범위 작음 |
| ~~D. 번개장터 약관 확인 후 재검토~~ | 작업지시자 결정으로 제외 (2026-11-02) | - | - |

- 가격 성격 컬럼에 `참고가(일본판 환산)`, `사용자 등록가` 같은 값을 추가해 실거래가와 구분한다.
- 권장안: **A를 기본 자동 소스로, B를 국내 실거래 소스로 두고, 시연용 초기 데이터는 C로 채운다.**
