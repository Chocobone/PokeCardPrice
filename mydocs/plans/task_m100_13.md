# Task #13: 카드 상세 화면 — 수행 계획서

## 수행 목표

`/cards/:id` 자리 화면(#12)을 실제 카드 상세 화면으로 바꾼다. 카드 정보, 변형 × 소스별 가격 비교(원화 포함), 기간 평균가, 기간 선택형 추이 차트를 #8 API(`GET /cards/{id}`, `GET /cards/{id}/prices`)로 보여 준다.
#8 F1에서 미룬 원화 표시 방식을 이 타스크에서 정한다.

## 범위

1. **카드 정보**: 큰 이미지(`CardImage size="high"`), 이름, 한글 종 이름, 세트(이름·로고·발매일·카드 수), 번호, 희귀도, 언어 배지, 한글판 배지. 한글판 ↔ 일본판 연결 카드는 작은 카드로 보여 주고 상세로 이동한다.
2. **가격 비교**: 변형 × 소스별 최신가 표. 원화, 소스 통화 원래 금액, 가격 기준일, 환율 기준일, 오래된 가격 표시. 대표가는 화면 위쪽에 크게 보여 준다. 소스별 출처 문구를 표 아래에 둔다.
3. **추이 차트**: 기간 탭(7일·30일·90일·1년), 변형 선택, 소스별 선. 선택한 기간의 요약(현재가·평균가·최저·최고·변동률)을 차트 옆(모바일은 아래)에 둔다. 점에 마우스를 올리거나 누르면 그날 값을 보여 준다.
4. **상태 처리**: 로딩, 오류(다시 시도), 없는 카드(404 → 찾을 수 없음 안내), 시세 없음, 이력이 짧음(점 1개). 브라우저 탭 제목은 카드 이름.
5. **상태 관리**: 카드 상세·추이 스토어(카드 ID·기간별 보관, 같은 화면으로 돌아오면 다시 요청하지 않음, 카드를 바꾸면 이전 요청 취소).
6. **원화 표시 방식** (#8 F1, Q2): 상세 화면과 홈·검색의 가격 표시 방식을 정해 적용한다.
7. **확인·문서**: `typecheck`·`lint`·`build`, 헤드리스 Chromium으로 데스크톱·모바일 폭, 밝은·어두운 모드, 실제 API와 목업 모드에서 확인한다. `frontend_structure.md`를 갱신한다.

## 핵심 설계 원칙

- **계약 타입만 의존**: 화면은 `api/types.ts`·`api/cards.ts`만 쓴다. 목업 모드에서도 같은 화면이 동작한다.
- **변형 × 소스를 섞지 않는다**: 소스마다 붙는 변형과 가격 차이가 크므로(#8 발견 사항) 가격은 변형·소스 단위로 보여 주고, 화면이 임의로 평균을 내지 않는다. "평균가"는 API의 기간 평균(`summary.average`)이다.
- **차트는 원화로 비교**: 소스 통화가 다르므로(USD·EUR) 차트는 원화 값으로 그려 한 축에서 비교한다. 원화가 없는 점(환율 없음)은 선을 끊는다 (Q3).
- **#12 규칙 유지**: CSS 변수, 상승 빨강·하락 파랑, 모바일 기본 반응형, 두 단어 이상 컴포넌트 이름, 스토어에는 API 결과·로딩·오류만.
- **의존성 최소화**: 차트도 패키지 없이 SVG로 직접 그린다 (Q1, #12 Q2와 같은 방향).
